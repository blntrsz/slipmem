Tags are optional frontmatter metadata, not directories. A tag is an ASCII lowercase kebab-case slug of at most 64 characters: letters and digits separated by single hyphens. `slugifyTag` decomposes Unicode, strips combining marks, lowercases, replaces other runs with hyphens, and truncates on a hyphen boundary. A value that normalizes to empty is rejected; duplicates are removed.

`tags` is canonical. The former `topics` key is read as tags when `tags` is absent or null; a note with both non-null is rejected because a rewrite could silently choose one. The next write always emits `tags`, so saving migrates the old key. Empty tag lists are omitted.

Tags do not affect a note's path or stable ID. They filter list and search results with exact normalized matching, feed `tags` counts (default 50, maximum 200, sorted by count then slug), and drive wiki selection. A wiki request normalizes its tag first and prefers exact tag membership over title, reference, and body text matches. Tag pages are generated, not stored as notes.
